# מערכת בקרת כניסה לחניה לפי זיהוי לוחית רישוי (ANPR)

מסמך אפיון — גרסה 1.0
מצב: כניסה בלבד (נתיב זיהוי יחיד)

---

## 1. סקירה כללית

מצלמת IP בכניסה לחניה מזהה את לוחית הרישוי של רכב שעוצר לפני השער. המערכת בודקת את הלוחית מול מסד נתונים של רכבים מורשים, כולל חלונות זמן (ימים ושעות). אם הרכב מורשה ברגע הנוכחי — נשלחת פקודה למודול ממסרים, שפותח את השער. כל מעבר (אישור או דחייה) נרשם ביומן עם צילום הלוחית.

עיקרון מנחה: **הסוכן המקומי באתר הוא הרשות המכריעה.** הוא מחזיק עותק מקומי של רשימת ההרשאות ומקבל את ההחלטה בעצמו, כך שהשער ממשיך לעבוד גם אם האינטרנט נופל. ה‑Cloud משמש לניהול, סנכרון ויומן בלבד.

שלוש שכבות:

1. **שכבת חומרה באתר** — מצלמה, מודול ממסר, בקר שער. כולם על אותו LAN.
2. **Local Gate Agent** — שירות Node.js על מיני‑PC באתר. הלב של המערכת.
3. **שכבת ניהול בענן** — Supabase + דשבורד Next.js ל‑CRUD על רכבים/הרשאות וצפייה ביומן.

## 3. רכיבי חומרה (BOM)

| רכיב | מפרט מומלץ | הערות |
|------|-----------|-------|
| מצלמת IP | 4MP, WDR אמיתי, עדשה varifocal 2.8–12mm (או קבועה 2.8mm), PoE, IP66/67 | עדשה רחבה — לכסות גם לוחית מכונית נמוכה וגם משאית גבוהה |
| תאורת תוספת | LED לבן רציף חלש, מכוון לאזור הלוחית | מונע "הצפת IR" על לוחית רפלקטיבית בלילה; נותן תמונה צבעונית למנוע הזיהוי |
| מודול ממסרים | 8ch Modbus TCP, PoE, 1NO 1NC, ≤10A (הדגם שנבחר) | משתמשים בערוץ אחד; שאר הערוצים עתודה |
| מתג PoE | לפחות 2 פורטי PoE | מזין גם את המצלמה וגם את מודול הממסר |
| מיני‑PC | x86 קטן, Linux, 8GB RAM, SSD, פעיל 24/7 | מריץ את הסוכן + מנוע ה‑LPR בלוקאלי |
| בקר שער | קיים, עם כניסת dry contact ("לחצן"/"פתיחה") + loop/photocell בטיחות | יש לוודא שה‑loop מחובר כדי שלא ייסגר על משאית |

**מנח התקנה:** מצלמה בגובה ~1.2–1.4 מ', מוטה מעט כלפי מטה, חזיתית ככל האפשר ללוחית (לא 45°). שאיפה ל‑100–150px רוחב על הלוחית. מודול הממסר וה‑PC בארון השער.

## 4. רכיבי תוכנה

### 4.1 Local Gate Agent (Node.js / TypeScript)
תפקידים:
- קליטת זרם המצלמה (RTSP) או דגימת frames בעת תנועה/טריגר.
- הרצת זיהוי לוחית (ראה §8).
- נרמול הלוחית והכרעה מקומית מול מטמון ההרשאות (ראה §7).
- שליחת פקודת פתיחה למודול הממסר (ראה §9).
- רישום אירוע מקומי + העלאת אירוע וצילום ל‑Supabase (תור עם retry; עובד גם offline ומשלים כשהחיבור חוזר).
- סנכרון תקופתי של רשימת הרכבים והכללים מ‑Supabase למטמון מקומי (SQLite).
- שליחת heartbeat (`last_seen`) לטבלת המכשירים.

### 4.2 שכבת ניהול — Supabase
- **Postgres**: טבלאות רכבים, כללי הרשאה, יומן מעברים, מכשירים, פעולות ידניות (ראה סכמה נפרדת).
- **Auth**: כניסת מנהלים לדשבורד; תפקידים `admin` / `viewer`.
- **Storage**: צילומי לוחיות (bucket פרטי, גישה מבוקרת בלבד).

### 4.3 Dashboard — Next.js 14 (Vercel), עברית RTL
- ניהול רכבים: הוספה/עריכה/השבתה, סוג רכב, שם בעלים, הערות.
- ניהול כללי הרשאה לכל רכב: תמיד / חלון שבועי / טווח תאריכים / חד‑פעמי.
- יומן מעברים חי: זמן, לוחית שזוהתה, החלטה, סיבה, ביטחון, צילום.
- כפתור פתיחה ידנית (נרשם בנפרד כפעולת מנהל).
- חיפוש לפי לוחית/שם/תאריך; סינון לפי החלטה.
- מסך מצב מכשיר (online/offline, last_seen).
- התראות על "לוחית לא מוכרת" (אופציונלי — email/push).

## 5. זרימת עבודה (רצף)

1. רכב עוצר לפני השער → המצלמה מספקת frame.
2. הסוכן מריץ LPR → מקבל מחרוזת לוחית + ציון ביטחון.
3. נרמול: השארת ספרות בלבד, אורך 7–8.
4. **Debounce**: אם אותה לוחית כבר טופלה ב‑30 השניות האחרונות — התעלם (מונע פתיחות כפולות).
5. בדיקת סף ביטחון (ברירת מחדל ≥ 0.80). מתחת לסף → לא מכריע, מנסה frame נוסף.
6. חיפוש רכב פעיל לפי הלוחית המנורמלת.
7. אם נמצא → בדיקת כללי ההרשאה מול הזמן הנוכחי (§7).
8. החלטה: `granted` / `denied` (+ סיבה).
9. אם `granted` → פקודת pulse למודול הממסר → השער נפתח.
10. רישום אירוע מקומי + העלאת אירוע וצילום ל‑Supabase.

## 6. מודל נתונים
ראה קובץ `anpr-gate-schema.sql`. סיכום הטבלאות:
- `vehicles` — רכבים מורשים (לוחית מנורמלת + תצוגה, בעלים, סוג, פעיל).
- `access_rules` — כללי הרשאה (אחד-לרבים מול רכב).
- `access_events` — יומן כל מעבר (כולל קריאות שנדחו ולא מזוהות).
- `gate_devices` — סוכנים/מכשירים באתר (IP ממסר, ערוץ, last_seen).
- `manual_actions` — פתיחות ידניות מהדשבורד.
- משתמשים — דרך Supabase Auth + טבלת `profiles` עם תפקיד.

## 7. לוגיקת הרשאות וחלונות זמן

לכל רכב יכולים להיות **מספר כללים**; די בכלל אחד שמתקיים כדי לאשר.

סוגי כללים (`rule_type`):
- `always` — מורשה תמיד.
- `weekly` — `days_of_week` (0–6) + `time_from`/`time_to`. מתקיים אם היום הנוכחי ברשימה והשעה בטווח.
- `date_range` — `valid_from`/`valid_to` (תאריכים). אופציונלית גם חלון שעות.
- `one_time` — תאריך בודד (`valid_from`). אופציונלית גם חלון שעות.

פסאודו‑קוד ההכרעה (רץ בסוכן המקומי, וגם כפונקציית Postgres לנוחות הדשבורד):

```
function isGranted(vehicle, now):
  if not vehicle.active: return false
  for rule in vehicle.rules where rule.active:
    switch rule.rule_type:
      case 'always':     return true
      case 'weekly':     if weekday(now) in rule.days_of_week
                            and timeInRange(now, rule.time_from, rule.time_to):
                            return true
      case 'date_range': if dateInRange(now, rule.valid_from, rule.valid_to)
                            and (rule.time_from is null or timeInRange(...)):
                            return true
      case 'one_time':   if date(now) == rule.valid_from
                            and (rule.time_from is null or timeInRange(...)):
                            return true
  return false
```

**אזור זמן:** כל הזמנים מחושבים ב‑`Asia/Jerusalem`. הסוכן מסתמך על שעון מקומי מסונכרן (NTP).

**נרמול לוחית ישראלית:** הסרת מקפים/רווחים, ספרות בלבד. אחסון בשדה `plate` המנורמל; שדה `plate_display` לתצוגה מעוצבת (XX-XXX-XX / XXX-XX-XXX).

## 8. אינטגרציית זיהוי לוחיות (LPR)

האתגר המרכזי: לוחיות ישראליות. אפשרויות (בחירה אחת, מאחורי ממשק `IPlateRecognizer` כדי שניתן יהיה להחליף):

1. **Plate Recognizer — Snapshot SDK (מומלץ להתחלה).** רץ on‑premise ב‑Docker על המיני‑PC, ללא GPU. הסוכן שולח frame ומקבל JSON עם הלוחית, ביטחון ותיבת גבול. הגדרות: `regions=il`, מצב strict לפורמט הנומרי.
2. **YOLOv8 + OCR נומרי (עצמאי).** גלאי לוחית מאומן + OCR לספרות. הלוחית הישראלית נומרית בלבד → ה‑OCR פשוט. דורש אימון/כיוונון אך חינמי ובשליטה מלאה.

הסוכן מצפה מה‑recognizer להחזיר אובייקט אחיד:
```ts
interface PlateRead {
  plateRaw: string;      // כפי שזוהה
  plateNormalized: string; // ספרות בלבד
  confidence: number;    // 0..1
  imagePath: string;     // צילום מקומי שיועלה ל-Storage
  capturedAt: string;    // ISO, Asia/Jerusalem
}
```

## 9. אינטגרציית ממסר (Modbus TCP)

מודול 8 ערוצים, Modbus TCP, פורט ברירת מחדל 502. משתמשים בערוץ יחיד (להגדרה ב‑`gate_devices.relay_channel`).

**שיטה ראשית — דופק בטוח (אמין, לא תלוי בפענוח מדויק של המודול):**
```
1. Write Single Coil (FC 0x05) על הערוץ → 0xFF00 (ON)
2. השהיה ~600ms
3. Write Single Coil (FC 0x05) על הערוץ → 0x0000 (OFF)
```
ב‑Node.js עם `modbus-serial`:
```ts
const client = new ModbusRTU();
await client.connectTCP(relayIp, { port: 502 });
client.setID(unitId);            // לרוב 1
await client.writeCoil(channel, true);
await sleep(600);
await client.writeCoil(channel, false);
client.close();
```

**אופטימיזציה (אופציונלי):** למודול יש פונקציית flash-on/flash-off מובנית (סגירה אוטומטית אחרי זמן מוגדר). אם רוצים — לוודא מול מדריך המודול את כתובת הרגיסטר ויחידת הזמן, ולהשתמש בה במקום שתי הכתיבות. שיטת הדופק מעלה עובדת בכל מקרה.

**חיווט:** ערוץ הממסר (COM + NO) מחובר לכניסת "לחצן/פתיחה" (dry contact) של בקר השער. אורך הדופק מכויל כך שהבקר יקלוט לחיצה אחת.

## 10. אבטחה ופרטיות

- צילומי לוחיות = מידע אישי. שמירה ב‑Storage bucket **פרטי**; גישה רק למשתמשים מאומתים עם תפקיד מתאים.
- **מדיניות שמירה (retention):** מחיקה אוטומטית של אירועים וצילומים אחרי X ימים (ברירת מחדל 60). job מתוזמן (ראה סכמה / cron).
- שלט "המקום מצולם" באתר.
- כל התעבורה לדשבורד ול‑Supabase ב‑HTTPS. סודות (service keys) רק בצד שרת / בסוכן, לעולם לא בקוד הצד‑לקוח.
- מומלץ למקם את הממסר והמצלמה ב‑VLAN/רשת מבודדת; הסוכן מגשר.
- RLS ב‑Supabase: קריאה/כתיבה רק למאומתים; כתיבת אירועים רק ע"י הסוכן (service role).

## 11. עמידות וטיפול בתקלות

- **Offline:** הסוכן מכריע מול המטמון המקומי; אירועים נכנסים לתור ומועלים כשהחיבור חוזר.
- **Debounce / Cooldown:** התעלמות מאותה לוחית בתוך חלון של 30ש' (להגדרה) כדי למנוע פתיחות כפולות.
- **סף ביטחון:** קריאות מתחת לסף לא מכריעות; ניסיון frame נוסף.
- **כשל ממסר:** ניסיון חוזר + רישום שגיאה + התראה; כפתור פתיחה ידנית כגיבוי.
- **בטיחות שער:** הסתמכות על loop/photocell של הבקר (חובה למשאיות) — המערכת רק "לוחצת על הכפתור", הבטיחות באחריות הבקר.

## 12. ניטור והתראות

- `gate_devices.last_seen` (heartbeat כל ~30ש'); התראה בדשבורד אם מכשיר לא דיווח > 2 דק'.
- התראה אופציונלית על "לוחית לא מוכרת" / ריבוי דחיות.
- מד מצב: אירועים אחרונים, אחוז זיהוי מוצלח, זמן תגובה.

## 13. פריסה

- **סוכן:** Docker Compose על המיני‑PC — קונטיינר הסוכן + קונטיינר ה‑LPR (אם Plate Recognizer). אתחול אוטומטי (systemd/restart=always).
- **Supabase:** פרויקט מנוהל; הרצת המיגרציות מהסכמה.
- **דשבורד:** Vercel, משתני סביבה מצביעים ל‑Supabase.
- **משתני סביבה (סוכן):** `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `RELAY_IP`, `RELAY_PORT`, `RELAY_CHANNEL`, `RELAY_UNIT_ID`, `CAMERA_RTSP_URL`, `LPR_ENDPOINT`, `CONFIDENCE_THRESHOLD`, `COOLDOWN_SECONDS`, `DEVICE_ID`, `TZ=Asia/Jerusalem`.

## 14. בדיקות קבלה

1. רכב מורשה (כלל `always`) → השער נפתח, אירוע `granted` נרשם עם צילום.
2. רכב לא מורשה → השער לא נפתח, אירוע `denied` נרשם.
3. כלל `weekly` מחוץ לחלון → דחייה; בתוך החלון → אישור.
4. אותה לוחית פעמיים תוך 30ש' → פתיחה אחת בלבד (debounce).
5. ניתוק אינטרנט → רכב מורשה עדיין נכנס; האירועים מועלים אחרי חיבור מחדש.
6. ניתוק ממסר → רישום שגיאה + פתיחה ידנית עובדת.
7. לוחית ישראלית עם מקפים מנורמלת נכון ותואמת לרשומה.
8. צילומים נשמרים ב‑bucket פרטי ואינם נגישים בלי אימות.
